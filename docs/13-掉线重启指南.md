# 机器人掉线后的重启与恢复指南

> 适用：三角洲 QQ 机器人（v0.9.0，腾讯云 `39.106.135.148`）
> 目标：QQ 掉线、账号被踢、NapCat 掉线或机器重启后，按本指南快速恢复。
> 相关文档：`docs/03-部署与联调.md`（部署/NapCat 细节）、`docs/05-V1交接总结.md`（历史踩坑）。

## 0. 先判断是哪一层出问题

| 现象 | 可能原因 | 先看哪里 |
| --- | --- | --- |
| 群里发命令完全没反应 | NapCat 掉线 / QQ 登录失效 / bot 进程停止 | 两个 systemd 服务 + 两边日志 |
| bot 服务 active，但 NapCat 日志显示断开 | QQ 被腾讯踢下线、登录失效 | NapCat 日志 / WebUI 登录 |
| 服务重启后仍不回复 | QQ 需要扫码或短信验证 | NapCat WebUI |
| 服务器重启后不回复 | systemd 服务未启动 | `systemctl is-active` |
| 只有某个功能不回复 | 功能开关/数据源/缓存问题 | bot 日志里对应模块 |

**最重要的原则：bot 重启是安全的；NapCat 重启可能导致需要重新扫码/短信验证。**
所以先重启 `deltaforce-bot`，不要一上来就重启 `napcat`。

## 1. 快速检查（SSH）

```bash
ssh root@39.106.135.148

systemctl is-active deltaforce-bot napcat
systemctl status deltaforce-bot --no-pager
systemctl status napcat --no-pager

journalctl -u deltaforce-bot -n 120 --no-pager
journalctl -u napcat -n 120 --no-pager
```

重点看：

- `deltaforce-bot` 日志里是否有：
  - `Bot 3877496716 connected`（协议端已连上）
  - `机器人 3877496716 已上线`
  - `bot_offline` / `登录已失效` / `WebSocket ... closed by peer`
- `napcat` 日志里是否有二维码、登录失败、账号安全验证、`登录已失效` 等。

> 不要连续快速重试 SSH：失败连接会占用 sshd 预认证槽位（约 120 秒），
> 越试越连不上。失败一次后先等 1~2 分钟，或从云控制台重启。

## 2. 情况 A：bot 进程/服务停了，NapCat 正常

这是最简单的情况，不需要扫码。

```bash
systemctl restart deltaforce-bot
sleep 3
systemctl status deltaforce-bot --no-pager
journalctl -u deltaforce-bot -n 60 --no-pager
```

预期日志：

```
Bot 3877496716 connected
机器人 3877496716 已上线
直播订阅轮询已启动
每日密码缓存预热已启动
```

如果日志显示：

```
WebSocket ... closed by peer
机器人 3877496716 已离线
```

说明 bot 正常启动了，但 NapCat 侧没有连上，转到情况 B。

## 3. 情况 B：QQ 登录失效 / NapCat 掉线（需要重新登录）

### 3.1 先看 NapCat 状态和原因

```bash
systemctl status napcat --no-pager
journalctl -u napcat -n 150 --no-pager
```

常见原因：

- `你的账号当前登录已失效，请重新登录。`
- 被腾讯判定账号异常/风控下线。
- NapCat 重启后快速登录失败，需要验证码/新设备验证。

### 3.2 开 SSH 隧道访问 NapCat WebUI

WebUI 只监听服务器本机 `127.0.0.1:6099`，在本机新开一个终端保持不关：

```bash
ssh -L 6099:127.0.0.1:6099 root@39.106.135.148
```

### 3.3 取 WebUI token

在服务器上执行（不要把手输的 token 发到公开地方）：

```bash
cat /home/napcat/Napcat/opt/QQ/resources/app/app_launcher/napcat/config/webui.json
```

找到 `token` 字段，然后在本机浏览器打开：

```
http://127.0.0.1:6099/webui?token=<token>
```

### 3.4 扫码登录

- 在 WebUI 里点登录/扫码，用手机 QQ 扫码。
- 如果二维码过期，刷新 WebUI 获取最新二维码。
- 也可以在服务器上取自动保存的二维码图片（可能过期）：

```bash
ls -l /home/napcat/Napcat/opt/QQ/resources/app/app_launcher/napcat/cache/qrcode.png
```

用 `scp` 或 `deploy_server.py --get` 下载到本机查看。

### 3.5 密码回退登录（如果已配置）

NapCat 的 systemd drop-in 里可能配置了：

```ini
[Service]
Environment=ACCOUNT=3877496716
Environment=NAPCAT_QUICK_PASSWORD=<小号密码>
```

这样 NapCat 重启后会先尝试快速登录，失败后尝试密码登录。
但遇到 `needCaptcha` / `needNewDevice` 时仍需人工验证码/短信。

查看是否配置（不要打印密码值）：

```bash
systemctl cat napcat | grep -E 'ACCOUNT|NAPCAT_QUICK_PASSWORD' | sed 's/=.*/=<已配置>/'
```

### 3.6 什么时候需要重启 NapCat

优先在 WebUI 里热操作，避免重启。只有以下情况才考虑：

```bash
systemctl restart napcat
```

- WebUI 完全打不开；
- NapCat 进程卡死；
- QQ 进程无响应。

重启后可能需要重新扫码/短信验证，这是已知代价。

### 3.7 登录成功后

NapCat 会自动重连 bot 的 WebSocket。检查：

```bash
journalctl -u deltaforce-bot -n 60 --no-pager
```

预期：

```
Bot 3877496716 connected
机器人 3877496716 已上线
```

如果 bot 此时也是 stopped，先 `systemctl restart deltaforce-bot`。

## 4. 情况 C：服务器重启/宕机恢复

两个服务都是 systemd `enable` + `Restart=always`，正常情况下会自动起来。

```bash
systemctl is-active deltaforce-bot napcat
```

如果没起来：

```bash
systemctl start deltaforce-bot
systemctl start napcat
```

然后按情况 B 检查 QQ 是否需要重新登录。

## 5. 情况 D：账号反复被踢

这是 QQ 风控问题，不是代码问题。可做的：

1. 确认用的是**专用小号**，不要用主号；
2. 配置密码回退登录（`ACCOUNT` + `NAPCAT_QUICK_PASSWORD`）；
3. 不要频繁重启 NapCat；
4. 让账号正常聊天/加群、养号，降低被判定为机器人的概率；
5. 如果云服务器 IP 被高频风控，可考虑把 NapCat 放在家庭网络，通过反向隧道连到服务器上的 bot；
6. 仍然频繁被踢时，接受“掉线后人工扫码”的运维成本，或更换账号。

## 6. 常见坑

1. **不要手动改服务器 iptables**：原生部署下 8099 是 bot 进程直接监听
   `127.0.0.1:8099`；按端口批量删除规则可能误删 Docker/其他规则。
2. **bot 重启安全，NapCat 重启可能要扫码**：先 `deltaforce-bot`，后 `napcat`。
3. **不要连续重试 SSH**：失败会占满 sshd 预认证槽位。
4. **不要打印 `.env`**：里面可能有 `ORZICE_TOKEN`、`LLM_API_KEY`、`SUPERUSERS`、
   NapCat 密码等；排查时只 grep 需要的键。
5. **端口检查**：

```bash
ss -lntp | grep 8099
```

应该只看到 bot 进程在 `127.0.0.1:8099`。
6. **NapCat WebUI 端口**：`127.0.0.1:6099`，必须 SSH 隧道，不能直接公网访问。

## 7. 恢复后的验收清单

- [ ] `systemctl is-active deltaforce-bot` → `active`
- [ ] `systemctl is-active napcat` → `active`
- [ ] bot 日志出现 `Bot 3877496716 connected`
- [ ] bot 日志出现 `机器人 3877496716 已上线`
- [ ] 群里发 `/帮助` 有回复
- [ ] 群里发 `/每日密码` 有回复（白天命中当天缓存）
- [ ] 群里发 `/制造利润` 有回复（可能重新取 4 次资源）
- [ ] 日志没有持续 `ERROR` / `Traceback`

## 8. 一页速查

```bash
# 1. 看状态
systemctl is-active deltaforce-bot napcat
journalctl -u deltaforce-bot -n 100 --no-pager
journalctl -u napcat -n 100 --no-pager

# 2. bot 重启（安全）
systemctl restart deltaforce-bot

# 3. QQ 登录失效：开隧道 + WebUI 扫码
ssh -L 6099:127.0.0.1:6099 root@39.106.135.148
cat /home/napcat/Napcat/opt/QQ/resources/app/app_launcher/napcat/config/webui.json
# 浏览器：http://127.0.0.1:6099/webui?token=<token>

# 4. 只有在 WebUI/进程卡死时才重启 NapCat
systemctl restart napcat

# 5. 最终确认
journalctl -u deltaforce-bot -n 60 --no-pager
```
