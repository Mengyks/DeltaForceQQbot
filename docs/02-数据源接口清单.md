# 数据源与接口清单

> 版本：v0.2.0 ｜ 状态：已接入真实 token，字段语义已核对 ｜ 最后更新：2026-10-15

数据全部来自社区第三方平台（官方未提供公开 API）。**接口存在随时变更或停服的风险**，
因此适配层把换源成本控制在一层之内，并用真实录制的响应做契约测试。

## 1. 主数据源：三角洲数据帝开放平台

- Base URL：`https://orzice.com/workApi`
- 认证：所有请求带 `token` 查询参数（仅服务端使用，不入日志、不进缓存键）
- 接口文档：<https://work-api.apifox.cn>（每条接口的 `.md` 链接可直接抓取，规格清晰）
- SDK 参考：<https://github.com/orzice/DeltaForceApi>
- 交流群：791785919

**Token 与安全**：在 <https://orzice.com/work/> 开通服务后获取，写入 `.env` 的 `ORZICE_TOKEN`。
平台明确要求"千万不要暴露，请在服务器后台请求，且一定要缓存"——本项目的所有请求都经过带缓存的适配层，
且 token 不进入任何日志或缓存键。`.env` 已在 `.gitignore` 中排除。

## 2. 卡战备接口（v1 使用）

| 接口 | 路径 | 成本 | 参数 |
| --- | --- | --- | --- |
| 实时卡战备 V4 | `/v1/sjz_api/jzv4_zb` | 1 次资源 | `lv`：0=11.25万机密、1=18.75万机密、2=55万绝密巴克什、3=60万绝密航天、5=78万绝密监狱 |
| DIY 卡战备 | `/v1/sjz_api/jzv3_diy` | 10 次资源/成功、1 次/失败 | `zb` 目标战备值（1500~780000）、部位开关、`exchange` 军需处兑换 |

### 2.1 V4 接口的真实响应结构（已核对）

```
data: [                        # 7 个套装组
  {
    "name": "花费最少-单枪",    # 组名：单枪/双枪/兑换/大胸挂/实用优先/无配件/无枪械
    "zb": 550000,              # 该档位门槛（权威值，回复里展示的就是它）
    "count": 5,
    "dateT": "2026-10-15 18:30:39",
    "list": [                  # 5 套方案
      {
        "name": "花费最少-单枪",  # 与组名相同！同一组内方案名不唯一
        "index": 1,
        "jz": 550013,           # 总战备值
        "price": 489884,        # 总花费
        "cz": -60116,           # 花费 − 门槛（负值 = 比门槛少花）
        "data": [               # 装备明细
          {"type": "枪1-瞄具", "name": "3/7可调倍率狙击镜",
           "price": 73409, "jz": -14834,   # jz = 价格 − 战备值贡献
           "bl": -16, "jiazhang": 1, "grade": 4, "exchange": "", "pic": "..."}
        ]
      }
    ]
  }
]
```

字段语义与校验等式见 `docs/01-卡战备-功能设计.md` §2.3；
`tests/test_real_data.py` 用 5 个档位的真实响应锁定这些等式，平台一旦改口径测试会立刻失败。

### 2.2 更新频率与缓存

- V4 每分钟更新（每小时 9/19/29/39/49/59 分跳过；每日 3:00~8:00 每 5 分钟），生成数百条数据。
- **本项目缓存 4 小时**（按用户要求），因此实际调用频率远低于平台更新频率。
- DIY 接口约 3 秒返回，成本 10 次资源，当前关闭。

## 4. 辅助数据源：静态物品资料

- 仓库：<https://github.com/jiansenc/DeltaForceData>（按类别整理好的 JSON：护甲/头盔/胸挂/背包/枪械/9 类配件/道具）
- 字段：`objectID`、`objectName`、`grade`、`weight`、`length`/`width`、`desc`、`pic`、`protectDetail`（耐久/防护等级/瞄准与移动影响/防护部位）
- 用途：物品百科、装备详情、图片素材
- 限制：**不含战备值与价格**；最后更新于 2024-12，新版本物品可能缺失

其他参考：<https://github.com/luoy-oss/deltaforce_id>（角色/枪械/积分 ID 映射）。

## 6. 已确认与仍待确认

已确认（2026-10-15 真实响应）：

1. 五个档位的门槛：112500 / 187500 / 550000 / 600000 / 780000。
2. 字段语义（`jz`、`cz`、`bl`、`jiazhang`）与校验等式（见 §2.1 与 docs/01 §2.3）。
3. 套装组命名与兑换组的识别方式（组名含"兑换"）。
4. 同一组内 5 套方案共用组名，不能按名字去重。

仍待确认：

1. 各接口的实际计费价格与免费额度（需在平台控制台确认），据此复核成本估算。
2. `isZb=1`（物品级战备值）是否会开放；若开放可自建优化器，支持"指定预算/指定武器"等深度定制。
3. 游戏内实测抽查：把机器人给的方案与游戏内面板对照，确认门槛与战备值口径完全一致。
