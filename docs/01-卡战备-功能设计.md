# 卡战备 —— 功能设计

> 版本：v0.2.0 ｜ 状态：已实现，真实数据验证通过 ｜ 最后更新：2026-10-15

## 1. 功能是什么

《三角洲行动》烽火地带中，每个地图、难度有**入场战备值门槛**，玩家进图时全身装备的战备值必须达标。
玩家希望用**最低成本刚好达标**（超额达标会拉高匹配到的对手强度），这一行为俗称"卡战备"。

机器人解决的就是：**给定地图与难度，给出最省钱的达标配装**。

用户价值：省钱（比按门槛价值堆装备便宜数万哈夫币）、省时间（不用自己翻行情计算）、不超额。

## 2. 游戏机制与数据口径（已用真实响应核对）

### 2.1 战备值构成

| 计入战备值 | 不计入 |
| --- | --- |
| 武器（含配件）、头盔、护甲、胸挂、背包 | 子弹、药品、维修工具、钥匙卡、投掷物等消耗品 |

其他规则：制式装备不计入；背包内的武器不占战备值；破损装备战备值略低但市价便宜很多；
组队按全队平均战备匹配。

### 2.2 门槛（接口返回，权威值）

| 地图 | 难度 | 门槛 | 数据帝档位 |
| --- | --- | --- | --- |
| 零号大坝 / 长弓溪谷 | 机密 | 112,500 | lv=0 |
| 巴克什 / 航天基地 | 机密 | 187,500 | lv=1 |
| 巴克什 | 绝密 | 550,000 | lv=2 |
| 航天基地 | 绝密 | 600,000 | lv=3 |
| 潮汐监狱 | 绝密 | 780,000 | lv=5 |

> 常规模式不需要战备值，因此**不提供常规难度的卡战备**（用户明确要求）。
> 门槛以接口返回的 `zb` 字段为准展示，`config/gates.json` 里的数值仅用于菜单与错误提示。

### 2.3 字段语义（与直觉不同，已核对）

真实的字段含义如下（详见 `deltaforce_bot/models/loadout.py` 模块文档，测试在 `tests/test_real_data.py`）：

| 字段 | 实际含义 | 校验方式 |
| --- | --- | --- |
| 方案 `jz` | 整套**总战备值**（≥ 门槛，如 550013） | 与门槛比较 |
| 方案 `cz` | **花费 − 门槛**，负值即"比门槛少花" | 全部样本满足 `cz == price - zb` |
| 装备 `jz` | **该件价格 − 该件战备值贡献**（不是战备值本身） | 全部样本满足 `Σ(price − jz) == 方案 jz` |
| 装备 `bl` | 假账百分比 = `100 × jz / (price − jz)`；**负值 = 战备值虚高（划算）** | 与 price、jz 反推一致 |
| 装备 `jiazhang` | 0/1 标记，对应"是否战备值虚高"（`bl < 0`） | 样本一致（`bl == 0` 为取整边界，不做断言） |

"假账"的社区含义：物品显示战备值高于真实市价（枪械配件最明显，收藏品几乎没有）。
卡战备的本质就是利用这种价差低成本进图。

### 2.4 套装组结构

接口把一个档位的结果分成 7 个组：`花费最少-单枪`、`花费最少-双枪`、`花费最少-兑换`、
`大胸挂`、`实用优先`、`无配件`、`无枪械`（不同档位组集合略有差异），每组 5 套方案，共约 35 套。

- 同一组内 5 套方案名字相同、构成接近（例如护甲"几乎全新/破损"之别），价格差几百到几千哈夫币。
  因此**按名字去重会误删**，实现改为按装备构成签名去重。
- 兑换组（`花费最少-兑换`）通常最省，但需要玩家自备兑换券，所以默认排除，用户加「兑换」才展示。

**展示策略**：只详细展示最省的一套（避免 3 套几乎一样的方案刷屏），其余按"配装思路"各给一行备选。

## 3. 数据方案

使用平台计算好的结果（V4 档位接口），不自建优化器。原因是自建需要全量"物品 → 战备值"映射，
而该接口（`item_price_all?isZb=1`）目前被平台标注为【暂不开放】。详见 `docs/02-数据源接口清单.md`。

## 4. 缓存与额度（按用户要求）

| 数据 | 缓存 | 依据 |
| --- | --- | --- |
| 卡战备方案（按档位） | **4 小时**（`CACHE_TTL_TIER=14400`） | 用户确认战备价格 4 小时内变化不大 |
| DIY 自定义凑战备 | 1 小时（功能关闭中） | 10 次资源/请求 |

配套机制：同参数并发合并（多人同时查只发一次真实请求）、每人 2 次/分钟与每群 10 次/分钟限流
（测试群可白名单免限流）、当日额度熔断（默认 2000 次）。

回复里会标出数据源自身的更新时间；若用的是本机缓存且已超过 90 秒，会附注"（X 小时前的缓存）"，
让用户知道数据的新鲜度。

## 5. 交互设计（已实现）

命令：**`/卡战备 <地图> <难度> [兑换]`**

| 输入 | 行为 |
| --- | --- |
| `/卡战备` | 可查档位菜单与用法 |
| `/卡战备 巴克什 绝密` | 该档位最省方案 + 3 条其他思路 |
| `/卡战备 航天 绝密 兑换` | 含军需处兑换方案 |
| `/卡战备 大坝 机密` | 低门槛机密图 |
| `/卡战备 巴克什` | 该地图有多个难度 → 提示指定难度，例如 `/卡战备 巴克什 机密 / 绝密` |
| `/卡战备 监狱` | 只有一种难度 → 自动选中（潮汐监狱 绝密） |
| `/卡战备 大坝 绝密` | 提示"零号大坝没有绝密难度，可选：机密" |
| `/卡战备 大坝 常规` | 提示"常规模式不需要战备值，不提供卡战备建议" |
| `/凑战备 50000` | 功能关闭 → 说明原因与当前可用命令 |

容错：命令必须带 `/`（或全角 `／`）前缀；"集市"→巴克什、"航天"→航天基地、"长弓"→长弓溪谷等别名；
全角空格与全角数字均可识别。

**输出示例**（真实数据）

```

   · 枪1-瞄具 3/7可调倍率狙击镜  战备8.82万  花7.34万  假账-16%
   ...
其他配装思路（各取最省一套）：
· 实用优先：花费 48.55万（少花 6.45万）
· 花费最少-单枪：花费 48.91万（少花 6.09万）
```

排版规则：金额与战备值统一按「万」缩写（113200 → 11.32万，不足一万显示原数）；
装备行展示"战备值（=价格−jz）/ 花费 / 假账百分比"。

图片卡片（把方案渲染成图）暂未做：文本版信息密度已够，且群里发图有风控顾虑，列为可选迭代项。

## 6. 实现拆解（已落地）

```
plugins/gear_loadout.py              # 入口：正则规则 → 编排层 → 发消息
deltaforce_bot/services/commands.py  # 编排：解析 → 限流 → 取数 → 排版 → 错误映射
deltaforce_bot/services/text.py      # 解析（地图/难度/兑换/关键词）与排版（纯函数）
deltaforce_bot/services/gear_loadout.py # 业务：取数、筛选兑换、排序、选最省与备选
deltaforce_bot/models/gate.py        # 入口模型与解析（错误提示文案）
deltaforce_bot/models/loadout.py     # 配装模型（字段语义与派生属性）
deltaforce_bot/adapters/orzice.py    # 客户端：额度检查 → 缓存 → 合并 → 请求（重试 1 次）
config/gates.json                    # 地图 + 难度 → 档位
```

关键决策：

- **解析与排版是纯函数**，因此 126 个用例里大部分是毫秒级单测。
- **入口解析集中在 models/gate.py**，错误提示（缺难度、难度不存在、常规不支持）都在测试里锁定文案。
- **排序**：同档位门槛相同，按花费升序即平台"花费最少"口径；不再依赖未验证的 `cz` 排序。
- **去重**：按装备构成签名，而不是方案名（真实数据里同组方案同名）。
