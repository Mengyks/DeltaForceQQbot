# 每日密码（v3）

> 状态：功能已实现，待部署验收 ｜ 版本：v0.6.0 ｜ 更新：2026-10-23
>
> 数据源不是数据帝：改用两个**免费、无需 token** 的公开接口，按顺序自动换源。
> 本文记录接口实测结果、缓存/推送规则、配置与验收方式。

## 1. 需求（按用户确认）

| 项目 | 规则 |
| --- | --- |
| 缓存预热 | 每天北京时间 **00:05** 取当天密码并写入缓存 |
| 手动查询 | 群友发送 `/每日密码` 直接使用当天缓存，返回图片卡片 |
| 回复形式 | 图片卡片（六地图背景 + 大号密码）；渲染/发图失败自动回退文字 |
| 查询频率 | 同一个群 **5 分钟内最多触发一次** |
| 取数频率 | **同一天只向上游查询一次**，之后所有请求（含推送）都用当天缓存 |
| 定时推送 | 每天北京时间 **11:00** 推送到白名单群 |
| 推送目标 | 只推白名单群；`DAILY_PASSWORD_GROUPS` 为空时沿用 `CHAT_GROUPS` |
| 缓存 | 按北京时间自然日缓存，跨天后重新取；不把昨天的密码当今天发 |
| 推送去重 | 同一天每个群只成功推送一次；失败在补推窗口内重试 |
| 补推窗口 | 11:00 后的 60 分钟（可配置）；服务重启/QQ 掉线后仍有机会补推 |

> 预热时间按最终流程取 **00:05**（你说过 0:02，后面流程写的是 0:05；两者都可直接改
> `DAILY_PASSWORD_REFRESH_TIME`）。预热成功之后，白天的手动查询和 11:00 推送都只读缓存。

> 说明：需求里的“缓存 24 小时”实现为**按北京时间自然日缓存**。
> 这样 23:59 取到的数据不会在次日 0:01 被当成“今天”继续使用；
> 同一天内无论查询多少次，都只会在第一次成功取数时访问上游。

- 实测返回（2026-10-23）：

## 4. 数据流

### 4.1 手动查询

```
群消息 /每日密码
  → 插件匹配（priority=10, block=True；聊天插件不会再接管）
  → 每群 5 分钟冷却检查
  → service.get_today()
      ├─ 内存快照（同一个自然日）→ 直接返回
      ├─ SQLite 当天快照 → 载入内存后返回（重启后也命中）
      └─ 都没有 → 4399 → eleven（按配置顺序），成功后写 SQLite
  → 渲染卡片（按天缓存）→ 发送图片；渲染/发图失败回退文字
```

- 手动查询**不限制群**（与卡战备一致）；定时推送只发白名单群。
- 00:05 预热后，手动查询直接命中缓存；0:05 之前如果提前查询且没有缓存，会按需取一次，
  取数失败则回复“暂时获取不到今日密码”，不会写错误缓存，0:05 预热会继续补。
- 取数失败时回复“暂时获取不到今日密码，请稍后再试”，不会写缓存；过了冷却可再试。
- 卡片按「日期 + 来源 + 数据更新时间」在内存缓存，同一天只渲染一次；JPEG 约 217 KB。
- 冷却按群独立，保存在内存；重启后清空。

### 4.2 预热与定时推送

NoneBot 启动后会创建两个相互独立的 asyncio 循环（每 20 秒检查一次）：

```
预热循环（00:05 ~ 11:00，每 60 秒最多尝试一次）
  → 当天还没有缓存
  → 调用同一份 get_today()，成功后写 SQLite + 内存
  → 失败则每 60 秒重试，最多持续 15 分钟
  → 已有缓存后不再请求上游

推送循环（11:00 ~ 12:00，可配置补推窗口）
  → 当天该群未推送
  → 优先使用预热好的缓存（没有缓存才取数，且最多每 5 分钟重试一次）
  → 发送图片；图片发送失败回退同一份文字
  → 成功的群写入 push_log（同一天不再重复）
  → 失败的群在窗口内继续重试
```

- 群友在 00:05 之后的 `/每日密码` 查询直接命中预热缓存，不会重复调用免费接口。
- 00:05 时 bot 未连接或数据源还没更新：不写错误缓存，预热循环会重试。
- 11:00 时 bot 未连接：不消耗上游请求，等连接后（补推窗口内）再推。
- 单个群失败不影响其他群；日志对同一群每天只告警一次，避免刷屏。
- 补推窗口结束后当天不再推送；第二天 00:05 预热、11:00 正常推新的一天。

## 5. 配置

`.env` 新增（完整示例见 `.env.example`）：

```dotenv
DAILY_PASSWORD_ENABLED=true
DAILY_PASSWORD_SOURCES=4399,eleven
DAILY_PASSWORD_REFRESH_TIME=00:05
DAILY_PASSWORD_PUSH_ENABLED=true
DAILY_PASSWORD_PUSH_TIME=11:00
DAILY_PASSWORD_PUSH_WINDOW_MINUTES=60
DAILY_PASSWORD_GROUPS=
DAILY_PASSWORD_QUERY_COOLDOWN=300
DAILY_PASSWORD_DB_PATH=data/daily_password.sqlite3
DAILY_PASSWORD_TZ_OFFSET=8
DAILY_PASSWORD_TIMEOUT=15
DAILY_PASSWORD_HISTORY_DAYS=7
```

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DAILY_PASSWORD_ENABLED` | false | 总开关；关闭时命令回复“未启用”，不推送 |
| `DAILY_PASSWORD_SOURCES` | `4399,eleven` | 按顺序尝试；未知源会被跳过 |
| `DAILY_PASSWORD_REFRESH_TIME` | `00:05` | 北京时间；预热当天缓存 |
| `DAILY_PASSWORD_PUSH_ENABLED` | true | 只控制定时推送，不影响预热和手动查询 |
| `DAILY_PASSWORD_PUSH_TIME` | `11:00` | 北京时间；格式 `HH:MM`，无效会回退并告警 |
| `DAILY_PASSWORD_PUSH_WINDOW_MINUTES` | 60 | 补推窗口；0 按 1 分钟处理 |
| `DAILY_PASSWORD_GROUPS` | 空 | 推送群；空则沿用 `CHAT_GROUPS` |
| `DAILY_PASSWORD_QUERY_COOLDOWN` | 300 | 同一群手动查询冷却（秒） |
| `DAILY_PASSWORD_DB_PATH` | `data/daily_password.sqlite3` | 独立 SQLite |
| `DAILY_PASSWORD_TZ_OFFSET` | 8 | 服务器通常是 UTC，按 UTC+8 计算“今天”、0:05 和 11:00 |
| `DAILY_PASSWORD_TIMEOUT` | 15 | 单次 HTTP 超时（秒） |
| `DAILY_PASSWORD_HISTORY_DAYS` | 7 | 本地快照/推送记录保留天数 |

## 9. 已知限制

- 免费源是非官方接口，可能改字段、限流或停服；主源失败会自动换 eleven，两个都失败则当天暂时不可用。
- 当天一旦用备用源取到（没有地点说明），会按“同一天只取一次”的规则用到当天结束，不会因为主源稍后恢复而重新抓取。
- 00:05 预热失败时会每 60 秒重试，最多 15 分钟；之后由手动查询或 11:00 推送按需取数兜底。
- 4399 返回的门位置配图 URL 只保存在快照里，当前卡片使用的是本地地图背景，不依赖该 URL。
- 手动查询冷却和推送中的 bot 选择都是进程内存态；重启后冷却清空，推送去重仍由 SQLite 保证。
- 补推只在 11:00 后的窗口内进行；整天离线则当天不补。
- 服务器时区不影响功能，但必须在 `.env` 保持 `DAILY_PASSWORD_TZ_OFFSET=8`，否则“今天”、00:05 和 11:00 会偏移。
- 数据仅供参考，以游戏内为准。
