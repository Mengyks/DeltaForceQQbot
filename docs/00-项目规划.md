# 项目规划

> 版本：v0.2.0 ｜ 状态：v1 已实现并通过真实数据验证，待真实群联调 ｜ 最后更新：2026-10-15

## 1. 项目目标

上线一个为《三角洲行动》玩家提供数据服务的 QQ 群机器人，可长期稳定运行在 Linux 云服务器上。

**成功标准**

1. 服务可用：群内发命令能稳定得到正确结果，异常时有友好提示而不是沉默或报错刷屏。
2. 数据准确：展示的战备值、价格、门槛与游戏内（及数据源平台页面）一致。
3. 响应快速：常规查询 3 秒内返回（命中缓存时几乎即时）。
4. 成本可控：第三方接口额度消耗可控，有缓存与限流保护。
5. 交付路径：本机 Windows 测试通过 → Docker 打包 → Linux 云服务器上线。

## 2. 服务范围与优先级

### v1：卡战备（已完成）

命令为 `/卡战备 <地图> <难度> [兑换]`，详见 `docs/01-卡战备-功能设计.md`。

- 最省方案 + 其他配装思路，量价对照（战备值 / 花费 / 假账比例）
- 4 小时缓存与额度保护
- 凑战备（自定义目标战备值）因成本高暂时关闭，代码保留可随时恢复

### v2：群聊机器人（代码已实现，配置后启用）

在指定群内接入 DeepSeek V4.1 Flash，支持群共享上下文、@/跟进窗口、图片/表情包理解；
只开群聊，不开私聊。实现与配置见 `docs/06-LLM群聊机器人.md`。

原计划的“每日密码”不再作为 v2 内容。

### v3：每日密码（已完成，待部署）

按用户 2026-10-23 的决定，V3 先做每日密码：每天 0:05 预热当天缓存、11:00 推送到白名单群，
群友也可发 `/每日密码` 查询；使用免费的 4399 游戏盒 / eleven.icu 接口，同一天只取一次并缓存。
实现与配置见 `docs/08-每日密码.md`。

原计划的制造台利润顺延到后续版本：特勤处制造利润、军需处兑换收益需要先确认接口口径
（平台同时提供"官方数据（标注不准）"与"自有源计算 Pro"两个版本），并明确展示哪一个。

### v4：主播开播监听

监听指定主播是否开播并推送到群。**与前三项不同，这部分不依赖数据帝**，需要先确定：

- 平台范围：B 站 / 抖音 / 斗鱼 / 虎牙（各平台开放程度不同，B 站有公开 API 最可行）
- 监听对象与推送目标：哪些主播、推到哪些群、是否支持多人订阅
- 轮询频率与限流：开播检测通常 1~5 分钟一轮，需要控制请求量
- 合规：只做"是否开播"状态查询与提醒，不抓取直播内容

### 待定

交易行行情查询、物品百科、个人战绩（需玩家扫码登录，风控与维护成本最高）。等前四项稳定后按需再排。

## 3. 技术选型

| 项目 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.13 | 异步生态成熟；本地与原生部署统一 |
| 框架 | NoneBot2 2.5 | 插件化、异步、类型友好，便于按服务逐步扩展 |
| 协议 | OneBot v11 | 业务代码不绑定具体协议端 |
| 协议端 | NapCat | Windows 本机调试方便；Linux 用原生安装 + systemd |
| 数据 | 三角洲数据帝开放平台 | 提供现成的卡战备计算与全量行情，是当前唯一可行来源 |
| HTTP | httpx（异步） | 避免阻塞事件循环 |
| 配置 | pydantic-settings + `.env` | 类型校验、敏感信息不入库 |
| 存储 | 内存缓存 + SQLite（v2 聊天） | 卡战备仍用内存缓存；群聊上下文持久化到 `data/chat.sqlite3` |

## 4. 架构

```
┌──────────────────────────────┐
│  QQ 群用户                    │
└───────────┬──────────────────┘
            │ 消息
┌───────────▼──────────────────┐
│  NapCat（协议端，独立容器）     │  OneBot v11
└───────────┬──────────────────┘
            │ 反向 WebSocket
┌───────────▼──────────────────────────────────────────┐
│  NoneBot2 应用                                        │
│  ├─ 接入层  plugins/   命令匹配与消息收发               │
│  ├─ 编排层  services/commands.py  解析→限流→取数→排版   │
│  ├─ 服务层  services/  业务逻辑（与框架无关，可单测）    │
│  ├─ 数据层  adapters/  客户端 + 4 小时缓存 + 合并 + 额度 │
│  └─ 配置    config/gates.json  地图+难度 → 接口档位      │
└───────────┬──────────────────────────────────────────┘
            │ HTTPS + token
┌───────────▼──────────────────┐
│  数据帝开放平台 API            │
└──────────────────────────────┘
```

**目录结构（已落地）**

```
DeltaForceQQbot/
├── bot.py                        # 启动入口（日志接管 + 关闭时释放连接）
├── config/gates.json             # 地图 + 难度 → 档位（改配置不改代码）
├── deltaforce_bot/
│   ├── config.py                 # .env → Settings
│   ├── logging_setup.py          # 标准库 logging → loguru
│   ├── runtime.py                # 运行时装配
│   ├── adapters/                 # orzice / cache / quota / ratelimit
│   ├── models/                   # gate（入口解析）、loadout（配装模型）
│   └── services/                 # gear_loadout（业务）、commands（编排）、text（解析排版）
├── plugins/gear_loadout.py       # NoneBot 插件入口
├── scripts/                      # mock_api_server / fake_onebot_e2e / demo_reply / record_fixture
├── tests/                        # 126 个用例（含真实响应契约测试）
└── docs/
```

分层原则：插件层不含业务逻辑；业务逻辑不依赖框架；外部数据统一经 `adapters`，
换数据源只改一层，且能脱离网络与 QQ 做全链路测试。

**贯穿性机制**

1. **缓存**：卡战备方案 4 小时（`CACHE_TTL_TIER`），token 只在服务端使用。
2. **额度保护**：群/用户级限流、同参数并发合并、当日额度熔断（默认 2000 次）。
3. **降级**：超时/失败重试一次，仍失败给友好提示；数据源错误码、404、非 JSON 均映射为可读提示。
4. **可观测**：结构日志记录命令行、耗时、额度消耗与缓存命中（已修好 NoneBot 2.5 不接管标准库日志的问题）。

## 5. 部署路线

| 阶段 | 环境 | 形态 | 验收 |
| --- | --- | --- | --- |
| 本地开发 | Windows 本机 | NapCat 桌面端 + `python bot.py` | ✅ 真实 token 端到端通过 |
| 容器化 | Windows 本机（Docker Desktop） | `docker compose up -d bot` | ✅ 镜像构建、健康检查、真实数据收发均通过 |
| 上线 | Linux 云服务器（39.106.135.148，已装 Docker） | `docker compose up -d`（bot + NapCat） | 待执行 |

容器化要点：

- 镜像 `deltaforce-qqbot:0.1.0`，非 root 运行，内置 TCP 健康检查；`.env` 不打进镜像。
- **PyPI 访问不稳**：镜像内默认用清华源构建，否则会因 SSL 中途断连失败。
- Windows 上 Docker Desktop 需先启动；Git Bash 传 `-v`/`/v1/...` 参数前需 `export MSYS_NO_PATHCONV=1`。
- 服务器部署时注意：机器人只需被本机 NapCat 访问，端口不必对公网开放；建议用 SSH 密钥登录而不是密码。

## 6. 风险清单与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 第三方 API 停服/改版（已有先例：`df-api` 文档停维护、`DeltaForcePrice` 停止更新） | 核心功能不可用 | 适配层隔离换源；真实响应进 fixture 做契约测试，口径一变立刻报警 |
| 接口额度消耗 | 额度耗尽 | 4 小时缓存 + 并发合并 + 限流 + 日额度熔断，日均 ≤30 次 |
| 平台字段语义变更（如 cz/jz 口径调整） | 展示错误数字 | `tests/test_real_data.py` 用等式断言锁定语义，改口径即测试失败 |
| 游戏版本更新导致门槛变化 | 数据过期 | 门槛以接口返回的 `zb` 为准；`config/gates.json` 仅用于菜单与错误提示 |
| NapCat 账号风控 | 掉线/封号 | 用小号、限频、不做敏感行为 |
| 合规边界 | 潜在纠纷 | 不做自动化游戏操作；不收费牟利；只读公开数据 |
| 凭据泄露 | token/服务器被滥用 | `.env` 与服务器密码不入库；建议改用 SSH 密钥；token 泄露后可在平台重置 |
