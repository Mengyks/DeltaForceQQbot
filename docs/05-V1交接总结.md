## 0. 一句话现状

QQ 群里发 `卡战备 巴克什 绝密`，机器人回一张**图片配装卡片**。代码在 GitHub
（`github.com/Mengyks/DeltaForceQQbot`，tag `v0.2.0`），线上跑在腾讯云 `39.106.135.148`。

## 1. 项目目标与范围

- 目标（用户原话）：上线一个为《三角洲行动》提供服务的 QQ bot；本机 Windows 测试 → 原生 systemd → Linux 云服务器。
- 服务路线：**v1 卡战备（已完成）** → v2 群聊机器人（代码已实现，配置后启用） → v3 特勤处制造利润 → v4 主播开播监听。
- 用户明确**不做**：适应监狱档位、永夜大坝（数据源不支持）、凑战备 DIY（成本高，配置开关已关）。

## 2. 已上线功能

### 2.1 卡战备（v1 主体，含图片卡片）

命令：`卡战备 <地图> <难度> [兑换]`

| 输入 | 行为 |
| --- | --- |
| `卡战备` | 档位菜单与用法 |
| `卡战备 巴克什 绝密` | 最省方案卡片 + 其他配装思路 |
| `卡战备 航天 绝密 兑换` | 含军需处兑换方案（通常更省，需自备兑换券） |
| `卡战备 az3 机密` | AZ3 新图（与零号大坝/长弓溪谷机密同门槛、共用缓存） |
| `卡战备 大坝 常规` | 明确回复"常规模式不需要战备值" |
| `凑战备 50000` | 功能关闭提示（改 `.env` 的 `CUSTOM_ENABLED=true` 可恢复，代码保留） |

数据流：消息 → 解析/限流 → 取数（**按 lv 缓存 4 小时**）→ 组装卡片数据 → Jinja2 模板 →
Playwright + Chromium 截图 PNG → OneBot `base64://` 图片段发送 → **发送成功后**才缓存图片（4 小时）。
渲染失败或发图失败自动回退文字版；缺图渲染灰色占位块。

卡片构成（按用户原型实现，见 `assets/items/html_prototype/原型.png`）：标题「地图——难度」（绝密红字/机密白字）、
红色分隔线、左侧四个装备位（头盔/胸挂/护甲/背包，**等级边框色** 1灰2绿3蓝4紫5金6红 + 耐久度标签 全新绿/几乎全新黄/破损红）、
右侧主武器1/主武器2/副武器（配件用文字「部位 名称」罗列，无配件显示"无需配件"）、
地图背景淡化、底部总战备/花费/比门槛少花 + 其他思路。含兑换的方案标注"含军需处兑换"与装备级"兑换"标签。

### 2.2 掉线监控

QQ 掉线时机器人无法自通知，因此：断开写日志 + 可选外部 webhook（`ALERT_WEBHOOK_URL`，支持 json/serverchan/feishu/dingtalk），
恢复后私聊管理员 QQ（`ALERT_QQ`）；阈值 `ALERT_MIN_DOWNTIME`（默认 30 秒）。**首次连接不通知**（防重启误报）。

## 3. 必须知道的事实（别重新验证）

### 3.1 数据源：三角洲数据帝开放平台

- Base URL `https://orzice.com/workApi`；token 在**本机 `.env` 的 `ORZICE_TOKEN`**（不入库，服务器上也有一份）。
- 接口文档 `https://work-api.apifox.cn`（每个接口有 `.md` 链接可直接抓）；平台要求"token 只在后台用且必须缓存"。
- 额度：卡战备接口 **1 次资源/请求**；`item_info_all` / `item_price_all` 是 20 次；DIY 是 10 次。日均消耗 ≤30 次（4 小时缓存下）。

**字段语义（用真实响应核对过，`tests/test_real_data.py` 锁定，改口径会让测试失败）**：

| 字段 | 含义 |
| --- | --- |
| 方案 `jz` | 整套**总战备值** |
| 方案 `cz` | **花费 − 门槛**（负值=比门槛少花） |
| 装备 `jz` | **价格 − 该件战备值贡献**（不是战备值本身！） |
| 装备 `bl` | 假账百分比（负=战备值虚高、划算） |
| 装备 `jiazhang` | 0/1 标记，对应 `bl < 0` |

**档位表**（`lv` 是接口参数；门槛以接口返回的 `zb` 为准）：

| 地图 | 难度 | 门槛 | lv |
| --- | --- | --- | --- |
| 零号大坝 / 长弓溪谷 / **az3** | 机密 | 112,500 | 0 |
| 巴克什 / 航天基地 | 机密 | 187,500 | 1 |
| 巴克什 | 绝密 | 550,000 | 2 |
| 航天基地 | 绝密 | 600,000 | 3 |
| 潮汐监狱 | 绝密 | 780,000 | 5 |

- 返回结构：`data[]`（7 个套装组：花费最少-单枪/双枪/兑换、大胸挂、实用优先、无配件、无枪械）→ 每组 5 套方案 → 每套 `data[]` 装备明细。
- **同一组内 5 套方案共用组名**（不能按名字去重）；兑换组最省但默认排除（需自备兑换券）。
- **永夜大坝：不支持**（`lv=4` 返回空数据、`lv=6/7` 报 400、文档与接口清单里都没有"永夜"）。适应监狱（`lv=4`，仅 V3-ALL 文档有）用户明确不要。

### 3.2 服务器与线上部署

| 项目 | 内容 |
| --- | --- |
| 机器 | `39.106.135.148`（腾讯云，Ubuntu，1.7 GB 内存 + 2 GB swap 已配置） |
| 机器人 | **原生 systemd 服务** `deltaforce-bot`，项目目录 `/opt/deltaforce-qqbot`，venv + Playwright Chromium（不再用 Docker 镜像） |
| 协议端 | **NapCat 原生安装**（非容器）：`/home/napcat`，systemd 服务 `napcat`，WebUI `127.0.0.1:6099` |
| 连接 | NapCat 反向 WS → `ws://127.0.0.1:8099/onebot/v11/ws`（配置见 `config/onebot11_3877496716.json`） |
| 账号 | 小号 `3877496716`；测试群 `1071781482`、`1130331921`（在 `.env` 的 `DEBUG_GROUPS` 里免限流） |
| 登录 | 用密码回退登录（systemd drop-in 里 `ACCOUNT` + `NAPCAT_QUICK_PASSWORD`），**重启后可能仍需短信验证** |

> 机器人已改为原生 systemd 部署；若服务器上仍是旧的 `deltaforce-bot` Docker 容器，
> 第一次执行部署脚本时加 `--stop-old-docker` 完成切换。

常用命令（本机）：

```bash
export MSYS_NO_PATHCONV=1     # Git Bash 必加，否则 /opt/... 参数会被改写成 Windows 路径

# 部署（默认原生：上传 → venv/依赖/Chromium → 安装 systemd → 重启）；资源不变时加 --skip-assets
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root

# 首次从旧 Docker 容器迁移时，加 --stop-old-docker 释放 8099 端口
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root --stop-old-docker

# 只改代码时（不传图片、不重装依赖）
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root \
  --skip-assets --skip-deps

# 单文件传输 / 远程执行命令
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root --put 本地 远端
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root --cmd "命令"

# 看日志
.venv/Scripts/python.exe scripts/deploy_server.py --host 39.106.135.148 --user root \
  --cmd "journalctl -u deltaforce-bot -f"
```

服务器上：`journalctl -u deltaforce-bot -f`（含额度消耗）、`systemctl status deltaforce-bot`、
`systemctl status napcat`、`journalctl -u napcat -f`。

### 3.3 已知坑（都会复发）

1. **NapCat 重启后需要短信验证**（快速登录被判"身份已失效"）→ 开隧道 `ssh -L 6099:127.0.0.1:6099`，
   浏览器 `http://127.0.0.1:6099/webui?token=<webui.json 里的 token>` 完成验证。
2. **不要连续重试 SSH**：失败连接会占满 sshd 预认证槽位（120 秒），越试越连不上。
3. **服务器连不上 Docker Hub**（加速站对 `python`/`ubuntu` 基础镜像返回 502）→ 生产已改原生部署，
   不再构建/传输 Docker 镜像；NapCat 也是原生安装。
4. **小内存机器装 Chromium 前先加 swap**（曾在 Docker 构建时把机器压死；原生引导同样适用）。
5. 本机：`github.com` HTTPS 不通（**SSH 可用，git 走 SSH**）、下载 GitHub 资源要带 Clash 代理
   `-x http://127.0.0.1:7890`、本地 Docker Desktop 要先启动、`grep` 被 ugrep 别名接管时用 `command grep`。
6. **图片资源不入库**：换机器/重装后要重新直传一次（`deploy_server.py` 默认会带上 `assets/`）。

## 5. 测试与验证手段

```bash
.venv/Scripts/python.exe -m pytest -q                 # 196 个用例，约 15 秒
.venv/Scripts/python.exe scripts/render_preview.py    # 用录制的真实数据渲染卡片到 assets/_preview/
.venv/Scripts/python.exe scripts/demo_reply.py        # 预览文字版回复
```

- 契约测试用 **5 个档位的真实响应**（`tests/fixtures/real/`）锁定字段语义与门槛；重录：
  `python scripts/record_fixture.py --path /v1/sjz_api/jzv4_zb --param lv=2 --out tests/fixtures/real/jzv4_zb_lv2.json`（会消耗额度）。
- **端到端不必等真实 QQ**：`scripts/fake_onebot_e2e.py` 可冒充 NapCat 连机器人（本机或服务器上均可），
  配合 `scripts/mock_api_server.py` 还能不花额度验证全链路。
- 真机验收：在测试群发命令，看机器人日志 `卡片渲染完成 / 回复卡战备查询（图片 N KB）` 与额度消耗。

1. **每次代码改动先给用户看**，用户确认后才提交推送 Git；版本号按里程碑递增并打 tag（已用 v0.1.0、v0.2.0）。

## 7. v2 群聊机器人（代码已实现，配置后启用）

v2 改为群聊机器人，不再做每日密码。实现与配置见 `docs/06-LLM群聊机器人.md`。

- 路线：现有 NoneBot 内新增插件，DeepSeek V4.1 Flash 走 OpenAI 兼容接口。
- 只开群聊（`CHAT_GROUPS` 白名单），群共享上下文；@/引用/叫名字立即回复，否则走跟进窗口；ambient 主动参与默认关闭（需要时可设 `CHAT_AMBIENT_ENABLED=true`）。
- 当前图片/表情包支持视觉分析；上下文存 SQLite，默认保留 7 天；本地表情包通过 send_meme 工具发送。
- `@机器人 上下文清理 提取摘要|直接清理` 仅 `SUPERUSERS` 可用。
- 还需要在 `.env` 填：`CHAT_ENABLED`、`CHAT_GROUPS`、`LLM_API_KEY`、`LLM_MODEL`、`SUPERUSERS`；
  人设写 `config/persona.md`。

其余待办：v3 特勤处制造利润（`422150879e0` Pro 版 / `396183651e0` 官方版标注"不准"）；
v4 主播开播监听（**不依赖数据帝**，需先确定平台范围 B站/抖音/斗鱼/虎牙与推送对象）。

**已知风险**：QQ 账号可能被风控踢下线（实测半天内两次，已配密码回退登录）；第三方数据源存在停服/改版风险（有先例），
契约测试会在口径变化时报警；本项目为非官方工具，不做自动化游戏操作类功能。
