# 制造台利润（v5）

> 版本：v0.8.0 ｜ 状态：已部署线上，待群内验收 ｜ 更新：2026-10-25
>
> 目标：群里发 `/制造利润`，返回特勤处四个制造台 **Lv3** 当前每小时利润最高的物品卡片。
> 只展示单次利润和每小时利润；数据源只用数据帝 Pro，不使用官方数据版。

## 1. 需求与已确认规则

| 项目 | 规则 |
| --- | --- |
| 制造台 | 技术中心、工作台、制药台、防具台，四个都做 |
| 等级 | 固定 **Lv3**，不提供 1/2 级 |
| 每台展示 | 只取 `price_hour` 最高的 **1 个物品** |
| 展示字段 | 单次利润 `price`、每小时利润 `price_hour` |
| 展示形式 | 图片卡片（2×2 四个台，物品图 + 等级边框色） |
| 查询方式 | 按需查询，发送命令才查；不做定时推送 |
| 缓存 | **12 小时**；缓存期内重复查询不再请求数据帝 |
| 数据源 | 数据帝 Pro `manufacturePro`，固定 `l=3` |
| 费用 | 每张卡片最多 4 次资源（四个台各 1 次）；正常最多 8 次/天 |
| 失败处理 | 单台失败显示“数据获取失败”；渲染/发图失败回退文字 |

## 2. 数据帝接口

### 2.1 使用接口

```
GET https://orzice.com/workApi/v1/sjz_api/manufacturePro?t=1&l=3&token=***
```

| 参数 | 含义 |
| --- | --- |
| `t` | 1 技术中心，2 工作台，3 制药台，4 防具台 |
| `l` | 部门等级，固定 3 |
| `token` | `.env` 的 `ORZICE_TOKEN` |

- 成功请求消耗 **1 次资源**；数据每 10 分钟更新。
- 复用了现有 `OrziceClient` 的缓存、额度、并发合并、错误映射，没有新建 HTTP 客户端。
- 官方数据版 `GET /v1/sjz_api/manufacture?t=1` 也消耗 1 次资源，但平台标注“不准”，
  且没有 `l` 参数；实测和 Pro Lv1/Lv2/Lv3 的价格都不一致，因此**不接入**。

### 2.2 字段口径（已用真实数据和全物品价格交叉核对）

| 字段 | 含义 |
| --- | --- |
| `name` / `pic` | 物品名、图片 URL |
| `grade` | 品质/等级（1~6） |
| `period` | 制造时长，单位小时，可能是小数 |
| `priceMax` | 交易行当前售价（未扣手续费） |
| `sxf` | 手续费（交易 + 上架） |
| `price` | **单次制造利润**（已扣材料成本和手续费） |
| `price_hour` | **每小时利润** = `price / period` |
| `unlockLevel` | 物品解锁等级 |
| `primaryClass` / `secondClass` | 一级/二级分类 |

验证例子（OLIGHT WARRIOR 3S战术手电）：

- `priceMax = 95,319`，和全物品列表 Pro 查到的交易行价格完全一致
- `sxf = 12,391`
- `price = 31,785`（单次利润）
- 推算材料成本 = `95,319 - 12,391 - 31,785 = 51,143`
- `price_hour = 7,063`，`31,785 / 4.5 = 7,063`

官方文档把 Pro 的 `price` 写成“真实到手价格”，与数据不一致；实际应按“单次利润”使用。
材料成本没有单独字段，卡片也不展示成本，只展示单次利润和每小时利润。

## 3. 四个台与图片映射

| 制造台 | 物品目录 | 等级目录 |
| --- | --- | --- |
| 技术中心 | `accessories`（配件）、`weapon`（枪械，平铺） | `level{grade}` |
| 工作台 | `bullet` | `level{grade}` |
| 制药台 | `supplies` | `level{grade}` |
| 防具台 | `helmets` / `backpacks` / `armor` / `chest_rigs`，按 `secondClass` 分 | `Level{grade}` |

### 3.1 宽松名称索引

物品名和磁盘文件名存在无法直接做文件名的差异：

- 前导点：`.300BLK_3` ↔ `300BLK_3`
- 空格/连字符：`MCX LT` ↔ `MCX-LT`
- 斜杠/下划线：`3/7` ↔ `3_7`
- 引号：`9号霰射"鼠弹"` ↔ `9号霰射鼠弹`
- 末尾下划线：`45 ACP Super` ↔ `45 ACP Super_`

`CraftingAssetLibrary` 的规则：NFKC → 小写 → 只保留字母/数字/中文。
找图时先按“制造台 + 等级目录”定位，等级目录大小写不敏感；同级找不到时兜底用同目录其他等级的图。
当前 Lv3 的 205 个物品已全部命中（205/205），没有归一化重名冲突。

### 3.2 资源情况

- 本地目录：`supplies 13`、`accessories 80`、`bullet 72`，以及原有的 `weapon`/防具目录。
- 服务器原先缺少 `supplies`、`accessories`、`bullet`，已上传（约 30 MB，`root:root 644/755`）。
- 新增/缺失的 8 张图已从 API `pic` 补齐，并和 API 图片 hash 核对一致。
- 子弹不同等级/型号共用同一张通用图是正常的（API `pic` 也如此）。

## 4. 卡片

原型：`assets/items/html_prototype/制作台利润原型.png`。

- 标题：`每日利润`
- 副标题：`特勤处制造 · Lv3`
- 标题下方：`查询时间：YYYY-MM-DD HH:MM`（这批数据的实际获取时间；缓存复用时保持不变，

- 卡片宽 920px，JPEG 质量阶梯 86→78→70→62，目标 350 KB，硬上限 600 KB
- 实测预览约 **84 KB**
- 预览脚本：`scripts/render_crafting_preview.py` → `assets/_preview/crafting_profit_preview.jpg`

只展示单次利润和每小时利润；不展示售价、手续费、材料成本。

## 6. 缓存与费用

- `OrziceClient.get(..., ttl=43200, cost=1)`：按 `(路径, t, l)` 缓存每个台的响应 12 小时。
- 图片卡片按“四个台最高物品签名”缓存 12 小时；数据不变时不重复渲染。
- 首次查询（缓存冷）：4 次请求；12 小时内再次查询：0 次。
- 正常最多 2 轮/天 = **8 次/天、约 240 次/月**；200,000 资源包按此用量可用几十年。
- 单台失败不会缓存完整图片，下次查询会重试失败台；已有缓存的其他台不重复请求。
- 缓存是内存态；服务重启会重新取 4 次（成本可忽略），没有新增数据库文件。

## 7. 配置

## 11. 已知限制 / 风险

- 数据帝接口是非官方第三方服务，可能改字段/限流/停服；适配层和真实 fixture 已隔离。
- 12 小时缓存意味着数据最多可能滞后 12 小时；按用户要求固定。
- 缓存为内存态，重启会重新取 4 次资源；不新增 SQLite。
- 官方数据版不接入：没有 Lv3 参数，价格和 Pro 不一致，平台自己标注“不准”。
- 只展示每台第一名；物品名较长时卡片最多两行，超出会截断。
- 如果某台全部负利润，仍显示最高的一条（红色），不隐藏。
- 图片名称归一化只做字符级处理，不做中文同义词/错别字模糊匹配；新增物品若名称差异较大，需要补图或加映射。
