# 图片卡片渲染设计

> 状态：技术路线已验证，HTML 原型待用户提供 ｜ 最后更新：2026-10-16

## 1. 技术路线（已在本机实测）

**Jinja2 模板 → HTML 文件 → Playwright 无头浏览器 → 截图 PNG → 通过 OneBot 图片段发送**

| 实测项 | 结果 |
| --- | --- |
| 输出体积 | 124 KB PNG（base64 后 166 KB，NapCat 直接可发） |
| 渲染耗时 | 浏览器冷启动 0.6 秒（只发生一次）；之后每次 0.4~0.6 秒（复用浏览器实例） |
| 中文渲染 | 正常 |

**两个必须遵守的实现细节**（实测踩过）：

1. 必须把 HTML 写成文件、用 `page.goto("file:///…")` 打开。用 `page.set_content()` 时页面没有 file:// 源，
   Chromium 会**拦截所有本地图片**（表现为裂图）。
2. 中文/空格文件名要 URL 编码（`urllib.parse.quote`）。

**容器侧待验证**（实现时第一件事）：镜像内需要 Chromium 与中文字体（`fonts-noto-cjk`），
否则中文渲染成方块。

## 2. 图片资源规则

### 2.1 目录结构

```
assets/items/
├── armor/<等级>/<装备名>.png       # 护甲，等级 1~6
├── helmets/<等级>/<装备名>.png     # 头盔，等级 1~6
├── backpacks/<等级>/<装备名>.png   # 背包，等级 1~6
├── chest_rigs/<等级>/<装备名>.png  # 胸挂，等级 1~5（没有 6 级弹挂）
├── weapon/<装备名>.png             # 枪械本体（不含配件）
└── backgrounds/<地图名>.png        # 卡片背景（巴克什 / 航天基地 / 潮汐监狱 / 长弓溪谷 / 零号大坝 / az3 …）
```

图片**不入库**（体积大：目前 55 MB / 172 个文件），`.gitignore` 已排除；用
`scripts/fetch_item_images.py` 可随时重新获取官方贴图。

### 2.2 部位（API `type`）→ 目录

| API `type` | 目录 | 是否用图片 |
| --- | --- | --- |
| 护甲 | `armor/<grade>/` | ✅ |
| 头盔 | `helmets/<grade>/` | ✅ |
| 背包 | `backpacks/<grade>/` | ✅ |
| 胸挂 | `chest_rigs/<grade>/` | ✅ |
| 枪1 / 枪2 / 手枪 | `weapon/` | ✅ |
| 枪1-瞄具 / 枪管 / 枪托 / 枪口 / 前握把 / 后握把 / 护木 / 弹匣（及枪2 同名系列） | — | ❌ **只用文字** |

**配件不用图片**（用户决定）：配件数量极多且贴图高度相似，玩家靠图也认不出来。
卡片上用文字「部位 名称」呈现，例如「瞄具 3/7可调倍率狙击镜」「枪托 QR高性能后托」。

### 2.3 等级与边框颜色

`grade` 取自接口的每件装备字段（护甲/头盔/背包/胸挂有效；枪械为 0/1，不用于配色）。

| 等级 | 颜色 |
| --- | --- |
| 1 | 灰色 |
| 2 | 绿色 |
| 3 | 蓝色 |
| 4 | 紫色 |
| 5 | 金色 |
| 6 | 红色 |

实测各部位出现的等级：护甲 1~5、头盔 1/2/3/5、背包 1~5、胸挂 1~4（游戏内上限 6，
按 1~6 全部预留颜色）。

### 2.4 名称归一化（查表规则）

查图时对「API 名称」与「文件名」都做归一化后比对：

1. 去掉耐久度后缀 `(破损) / (几乎全新) / (全新)`（含全角括号）；
2. 去掉所有空格（API 写作 `DAS 防弹头盔`，文件是 `DAS防弹头盔.png`）；
3. 统一括号为半角、忽略大小写。

> 实测：5 个档位中 13 款装备有多个耐久度变体，**13/13 共用同一张贴图**，因此去后缀是安全的。

### 2.5 缺图降级

找不到图片时渲染灰色占位块（显示名称首字），**不允许因为缺图导致整张卡片失败**。

## 3. 地图背景

卡片背景按「档位 → 地图名」取 `backgrounds/<地图名>.png`。
已确认的背景：巴克什、航天基地、潮汐监狱、长弓溪谷、零号大坝、az3。

**AZ3（新图）**：有机密与常规两种模式；机密模式门槛与「零号大坝 机密」「长弓溪谷 机密」完全相同
（lv=0），所以三者**共用同一份方案数据与缓存**，只是展示的地图名与背景图不同。
`config/gates.json` 已加入 `az3 / 机密 / lv=0`。

**永夜零号大坝：数据源暂不支持**（见 §5），因此不做。

## 4. 缓存

| 内容 | 策略 |
| --- | --- |
| 方案数据 | 按 `lv` 缓存 4 小时（键不含地图名 → 大坝/长弓/az3 三个入口天然共用一份） |
| 渲染图片 | 按「档位 + 方案签名 + 数据时间戳」缓存 4 小时；命中直接发图，不重复渲染 |
| 发送成功后再缓存（用户要求） | 渲染 → 发送 → 发送成功才写入图片缓存，避免缓存了发不出去的结果 |

## 5. 待办与开放问题

1. **HTML 原型**：等用户提供，据此写 Jinja2 模板。
2. **容器环境**：Chromium 安装方式 + 中文字体（`fonts-noto-cjk`），图片资源随卷挂载。
3. **适应监狱（lv=4）**：数据帝「V3 - 市场 - ALL」文档里把 `4` 定义为「24W 适应监狱」，
   但 V4 接口请求 `lv=4` 返回空数据（`lv=6/7` 直接 400）。是否要接入"适应监狱"档位待确认。
4. 配件文字样式、卡片整体版式：以用户原型为准。
